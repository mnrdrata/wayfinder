## Causes

### node-review-bug: new comment rule in the reviewer

PR #9 added "Comment bloat counts here and is BLOCKING" to `wf-reviewer.md`. The reviewer now routes comment
findings to BLOCKING, including the stale `// NOTE` line that was already on `main` and not touched by the
diff. The baseline routed the same comment to NON_BLOCKING. Both review attempts this run did the same,
so this is behavior, not judge variance.

Possible fix: limit the BLOCKING comment rule to comment lines the diff adds or changes. A comment the fix makes
stale stays NON_BLOCKING.

### ambiguous-spec: planner lost the "run /wf-spec" signal

PR #9 removed the planner instruction to open `SPEC_GAPS` with `ticket looks un-spec'd — run /wf-spec first`
when a ticket has no acceptance criteria. The planner still narrowed scope well (one documented defect, no
invented features), but no longer tells the human the ticket was vague. The baseline run did.

Possible fix: restore that one line in the planner's decide-don't-ask step.

## Harness deviations (this environment only)

This run executed from a background session isolated in a git worktree. That session's guard blocks git
commands that target other repos, including the fixtures, and the guard also applies to subagents. A normal
`/wf` or `/wf-eval` session doesn't have this guard. Effects:

- **Executors could not commit.** py-feature's executor finished its code but was blocked on commit. The
  node executors were told up front to leave changes uncommitted. Each execute stage was judged on
  `git diff main` of the working tree plus a sandboxed test run. Commit hygiene isn't a rubric item.
- **Review mutation was applied uncommitted**, not committed on the eval branch.
- **node-review-bug ran twice.** The first reviewer couldn't run `git diff main`, so it reviewed whole files
  without knowing what changed. It caught the guard and hollow-test flaws but missed the `sum` rename. That
  attempt was discarded as invalid. The scored attempt got the diff inline from the harness.
